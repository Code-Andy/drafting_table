# 2026-09-03 — v0.7.2 launch watchdog fix (still crashes on v0.7.1)

## User report

- v0.7.1 still exits after the beige launch screen on the physical iPad.
- Simulator gate passes, so this is a device-only launch kill, not a corrupt
  archive or SideStore install failure.

## Diagnosis

- Beige screen = `UILaunchScreen` + `MTKView.clearColor` committed, so the
  scene, window, and Metal clear color all work.
- v0.7.x rendered the full retained document **every display-refresh** even
  while idle: `snapshotForDisplay` + `NSValue` boxing + Catmull-Rom smoothing
  + one `MTLBuffer` per stroke per pass, at up to 120fps.
- On a physical iPad that first-frame workload stalls scene connection and
  the iOS watchdog kills the app. It looks like an instant crash.
- Engine archive loading (`DTEngine::loadArchive`, `DTPersistence::decode`)
  is already bounds-checked, so a corrupt autosave is a less likely cause.
- Deployment target was iOS 18.0, unnecessarily narrow for the APIs used.

## Changes

- `platforms/ipad/CanvasView.swift`
  - `enableSetNeedsDisplay = true`, `isPaused = true`, 60fps cap.
  - Exactly one frame is scheduled per input batch, tool toggle, transform,
    grid change, or document commit. Idle canvas costs zero frames.
- `platforms/ipad/Bridge/DTMetalRenderer.mm`
  - Early return on zero-size first layout.
  - Nil guards for command buffer and encoder.
  - `@try/@catch` around the display snapshot.
  - 220,000-vertex per-frame budget; excess geometry is truncated to whole
    triangles so a huge document degrades instead of OOM-killing launch.
- `platforms/ipad/DraftingTableViewController.swift`
  - Scene connection only applies settings and lays out rails.
  - Autosave restore + first `setNeedsDisplay` run on the next main-queue
    turn after the window is visible, with `NSLog` launch markers.
  - `viewDidAppear` kicks one explicit frame once layout has a real size.
  - Writes `Caches/DraftingTable-last-launch.txt` breadcrumbs
    (`viewDidLoad` / `restored` / `appeared`) for the next crash report.
- `project.yml`
  - Deployment target 18.0 → 17.5 (Pencil tap/squeeze/roll APIs need 17.5;
    17.0 was tried and fails to compile).
  - Version 0.7.2, build 10.

## Validation

- Windows-side: no compiler here; relies on CI `ipad-build.yml`
  (XcodeGen + device `xcodebuild` + simulator launch gate).
- Simulator gate must stay green; device validation is the user's iPad.
- If it still dies, ask for: iPad model, iPadOS version, and
  Settings → Privacy → Analytics → Analytics Data → latest
  `DraftingTable-*.ips`, plus the breadcrumb file stage.
