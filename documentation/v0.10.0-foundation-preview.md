# Drafting Table 0.10.0 foundation preview

This is the first reviewable build of the replacement iPad raster foundation.
It is intentionally narrower than the earlier 0.9.x prototype and is intended
for personal SideStore/AltStore sideloading, not App Store or TestFlight
distribution.

## Included in this preview

- one package-backed document with one fixed-size page;
- two stable-ID raster layers with selection, visibility, and opacity;
- Apple Pencil and direct-touch brush input through the existing coalesced and
  predicted UIKit sampling path;
- sparse 256-by-256 Metal raster tiles with one-pixel aprons;
- true destination-out erasing that reveals the lower layer or paper;
- layer opacity applied once when the layer's flattened tiles are composited;
- renderer-transaction undo/redo using copy-on-write GPU tile generations;
- asynchronous exact RGBA8 checkpoints and manifest-last package commits;
- recovery from the latest complete manifest and package reopening through
  Files;
- first-launch paper fitting, safe-area bottom chrome, hover and supported
  Pencil gesture plumbing;
- an unsigned arm64 IPA build with source-SHA and checksum provenance.

The retained-stroke renderer is no longer on the live drawing path. DTAR is an
explicit one-way import source only.

## Intentionally unavailable

Vector shapes/layers, Shade, bucket fill, raster/vector selections, image
import, page creation/reordering, PNG/PDF export, and retained-stroke
thumbnails are hidden or disabled. They must not return until they use the
same tile/version/package contracts.

## Architecture checkpoint

UIKit copies plain Pencil samples into a serial document coordinator. The
coordinator reserves operation and document generations. One serial Metal
queue owns all writable resident pixels and one sparse backend per stable
layer ID. A stroke freezes copy-on-write versions, commits them, and blits
exact tile interiors to shared staging buffers in ordered GPU work. Only the
command-buffer completion publishes history and hands immutable payloads to
the package actor. The actor writes tile objects and a versioned manifest,
then replaces `CURRENT` last. Persistence acknowledgement flows back to the
exact operation/version only after that publication succeeds.

## Personal sideload workflow

1. Use the successful `iPad unsigned IPA` artifact for the exact reviewed
   branch commit.
2. Verify `build-metadata.txt` beside the IPA and compare its `source_sha` and
   `ipa_sha256` values with the handoff summary.
3. Import `DraftingTable.ipa` into SideStore or AltStore and let that tool sign
   it with the personal Apple ID used on the iPad.
4. On first launch, draw on both raster layers, lower the upper layer opacity,
   erase upper-layer ink, undo/redo, background the app, relaunch, and confirm
   the same pixels reopen.
5. Report the iPad model, iPadOS version, Pencil model, visible seams or commit
   flashes, and whether the package reopened after force-quit.

## Assumptions made

- Distribution is one unsigned personal-sideload IPA. No store signing,
  TestFlight, App Store Connect, or public redistribution work is included.
- The deployment target remains iPadOS 17.5. Pencil Pro features are optional
  enhancements; brush and eraser have toolbar fallbacks.
- The preview page is 1536 by 2048 document points and has exactly two raster
  layers. Multi-page and mixed raster/vector documents are deferred.
- Loose immutable `.dtile` objects are acceptable for this preview. Packfiles
  or SQLite/WAL remain a required provider/file-count experiment before scale.
- The original Android app is a behavioral reference, not a visual oracle.
  Its active-layer bucket semantics are recorded, but bucket fill is disabled
  rather than silently changed.
- DTAR compatibility means one-way import only; the live app never dual-writes
  retained strokes and tile packages.
- Pencil estimated-value corrections are captured by the bridge, but rebaking
  an already emitted live GPU stroke from corrected estimates is deferred.
- CI can validate arm64 compilation, packaging, provenance, and simulator
  launch. Pencil latency, hover, haptics, provider behavior, and visual output
  still require the physical iPad check above.

## Known v0.1 risks for device testing

- Undo history and immutable GPU history are not yet pruned to the final byte
  budget; very long sessions need memory instrumentation.
- Package object garbage collection and tile compression are not enabled yet.
- Predicted tile aprons are finalized at commit; a transient seam during a
  rotated predicted tail remains a device-test item.
- The simulator smoke test proves launch survival, not Pencil latency or exact
  Metal pixels.
